React Composition and Hooks for Leaders

Evergreen Insurance Quote Page — Custom Hooks and Context

Lab 1

In this lab, you will refactor the Evergreen quote app using two patterns your engineers rely on to keep larger Liberty Mutual applications maintainable: a custom hook (reusable logic) and the Context API (shared state without "prop drilling"). The app you built in Week 3 already works — here you reshape how it is organized, not what it does on screen.

You are not expected to design React architecture in one hour. You are here to see why teams extract logic into hooks and reach for context — two phrases that come up constantly in React code reviews — by applying them to a page you already know well.

1.1. A Note About Keyboard Shortcuts

Your lab VM runs inside your browser, which can sometimes capture a keyboard shortcut before it reaches the VM. If a shortcut doesn’t work — for example, Ctrl+` to open the integrated terminal — use the menu alternative instead (Terminal → New Terminal). Every shortcut in this lab has a menu path.

1.2. Why You’re Doing This Lab

"Let’s pull that into a hook" and "this should be in context, not props" are among the most common architecture comments on a React team. After this lab, both will be moves you have made yourself — so you can weigh the trade-offs when your engineers propose them in a pull request.

1.5. The Refactor at a Glance

In this lab, you are mostly moving code that already works into better homes. Before you touch anything, here is the whole arc — five small changes, each building on the last:

  1. Create the hook (useQuoteEstimate.ts) — cut the quote logic out of the form and give it a reusable home.

  2. Use the hook (QuoteForm.tsx) — call the hook instead of keeping that logic inline.

  3. Create the context (QuotesContext.tsx) — build a shared "store" for the saved-quotes list.

  4. Provide the context (App.tsx) — wrap the page so everything inside can reach that store.

  5. Consume the context (RecentQuotes.tsx, then QuoteForm.tsx) — read and update the list directly, with no props threaded between components.

Think of it like reorganizing a filing cabinet: the documents don’t change, but where they live — and who can reach them — gets much cleaner. If a paste ever feels like it has no obvious home, come back to this list and check which of the five moves you are on.

 Tip

Every snippet below either replaces a numbered TODO comment or joins existing lines. When you are unsure where code goes, match the surrounding lines shown in the snippet — a // …​ comment always marks code that is already there and should stay.

1.6. Extract a Custom Hook

Right now, QuoteForm holds all the state and the premium math. You will move that logic into a reusable custom hook — a function whose name starts with use.

Think of a custom hook as a policy calculator you can hand to any agent. Today the calculation is welded inside one form; pull it into useQuoteEstimate and any screen — a full quote page, a sidebar widget, a chatbot — can pick it up and use it, each getting its own independent set of numbers. The use prefix is not just a name: it is a convention that tells React (and your teammates) "this function calls other hooks," and React relies on it to apply the rules that keep hooks working.

  1. Open src/hooks/useQuoteEstimate.ts. Fill in the three TODO`s so the hook owns the state and the derived values — `TODO 1 is the three pieces of state, TODO 2 is the derived isValid / premium / error, and TODO 3 is the object the hook returns:

    export function useQuoteEstimate() {
  const [type, setType] = useState<CoverageType>("auto");
  const [age, setAge] = useState(35);
  const [coverageAmount, setCoverageAmount] = useState(50000);

  const isValid = age >= 18 && age <= 100 && coverageAmount >= 10000;
  const premium = isValid ? calculatePremium(type, age, coverageAmount) : null;
  const error = isValid
    ? ""
    : "Enter age 18–100 and coverage of at least $10,000.";

  return {
    type, setType, age, setAge, coverageAmount, setCoverageAmount,
    premium, error, isValid,
  };
}

What you just did:

  • Moved three useState calls out of a component and into a plain function — that is all a custom hook is.

  • Kept the derived values (isValid, premium, error) next to the state they depend on.

  • Returned everything a component needs as one object, so any caller can destructure just the pieces it wants.

Why this matters: The hook now owns the quote logic. Any component — a full quote page, a sidebar widget, a modal — can call useQuoteEstimate() and get its own independent copy of that behavior. That is the entire point of custom hooks: share logic, not markup.

1.7. Use the Hook in QuoteForm

With the logic now living in the hook, QuoteForm no longer needs to know how a premium is calculated — it just calls the hook and renders the result. Picture swapping a car’s engine while leaving the dashboard untouched: the driver’s controls look identical, but what powers them now lives in a cleaner unit you can service on its own.

  1. Open src/components/QuoteForm.tsx. At the top of the file, import the hook alongside the existing imports:

    import { useQuoteEstimate } from "../hooks/useQuoteEstimate";

  2. Inside the component, replace the inline useState lines and the derived isValid / premium / error with a single call to your hook:

    function QuoteForm() {
  const {
    type, setType, age, setAge, coverageAmount, setCoverageAmount,
    premium, error, isValid,
  } = useQuoteEstimate();
  // ...the rest of the form stays the same

     Caution

    Delete the original useState calls and the old isValid / premium / error lines as you paste the hook call — don’t keep both. If TypeScript reports that type, age, or premium is declared twice, the old lines are still there; remove them. You can also drop the now-unused useState and calculatePremium imports.

  3. Save and check the browser — the form behaves exactly as before. Same behavior, cleaner component.

Why this matters: QuoteForm got shorter and now reads as "what the form looks like," while the hook holds "how a quote estimate works." Separating those two concerns is what engineers mean by "clean component."

1.8. Create the Quotes Context

The saved-quotes list is currently passed from App down to RecentQuotes as a prop. As an app grows, threading data through every layer ("prop drilling") becomes painful.

Picture prop drilling as passing a memo hand-to-hand down a line of employees just so the person at the very end can read it — everyone in between has to carry it even though it is none of their business. Context replaces that chain with a shared company system: any component can look the data up directly, no hand-offs required.

The file you are about to fill in has four parts, and two are already written for you. You will write the reducer (how the list changes) and the provider (who holds the list); the Action type and the useQuotes helper are done. Take it one TODO at a time.

  1. Open src/context/QuotesContext.tsx. Fill in the reducer (TODO 4) — for an "add" action, return a new array with the new quote at the front; for anything else, return the state unchanged:

    function quotesReducer(state: Quote[], action: Action): Quote[] {
  switch (action.type) {
    case "add":
      return [action.quote, ...state];
    default:
      return state;
  }
}

  2. Fill in the provider (TODO 5 and TODO 6):

    export function QuotesProvider({ children }: { children: ReactNode }) {
  const [quotes, dispatch] = useReducer(quotesReducer, sampleQuotes);
  const addQuote = (quote: Quote) => dispatch({ type: "add", quote });

  return (
    <QuotesContext.Provider value={{ quotes, addQuote }}>
      {children}
    </QuotesContext.Provider>
  );
}

     Note

    The useQuotes hook at the bottom of the file is already written for you. It wraps useContext and throws a clear error if a component tries to read the context without a QuotesProvider above it — the recommended pattern for context in a real codebase.

Why this matters: useReducer centralizes every way the list can change into one function. Think of the reducer as a claims-intake desk: you never scribble on the official ledger yourself — you file a request describing what happened (an action, like add), and the desk is the single place that decides how the records change. That discipline is why one small function can be trusted as the only source of truth for the list. It is also the exact idea behind Redux and most serious state management, so "action," "reducer," and "dispatch" are words your engineers reach for constantly.

1.9. Wrap the App in the Provider

  1. Open src/App.tsx. Import the provider, wrap the whole page in it, and drop the quotes prop you used to pass to RecentQuotes:

    import { QuotesProvider } from "./context/QuotesContext";

function App() {
  return (
    <QuotesProvider>
      {/* header, hero, ... */}
      <section className="quote-form-section">
        <QuoteForm />
        <RecentQuotes />
      </section>
      {/* footer */}
    </QuotesProvider>
  );
}

     Note

    After you save this, <RecentQuotes /> will show a TypeScript error — it still declares quotes as a required prop, which you just stopped passing. That is expected. You fix it in the next step, Read Context in RecentQuotes, where RecentQuotes starts reading the list from context instead of props.

Why this matters: Wrapping the page in <QuotesProvider> is like switching on Wi-Fi for a whole floor: everything inside its range can connect to the shared data, and you never run a cable to each device. Every component rendered inside can now read the quotes list, no matter how deep it sits in the tree — and App no longer has to hand that data to anyone directly.

1.10. Read Context in RecentQuotes

  1. Open src/components/RecentQuotes.tsx. Remove the quotes prop (and the RecentQuotesProps interface it used) and read from context instead:

    import { useQuotes } from "../context/QuotesContext";

function RecentQuotes() {
  const { quotes } = useQuotes();
  // ...the .map() stays the same
}

  2. Save. The recent-quotes list still renders — but now it gets its data straight from context, with no props in between.

Why this matters: App no longer needs to know or care that RecentQuotes wants the quotes list. Adding a new piece of shared data no longer means editing every component in the chain. That is the prop-drilling problem context solves.

1.11. Save a Quote into Shared State

This is the payoff. QuoteForm will add to the shared list, and RecentQuotes will show the result — even though neither component owns the other. Notice that QuoteForm never touches the list directly: it calls addQuote, which files an "add" request with the reducer desk you built earlier. The form’s only job is to say what happened; the reducer decides how the list changes.

  1. In src/components/QuoteForm.tsx, read addQuote from context and add a save handler:

    import { useQuotes } from "../context/QuotesContext";
// inside the component:
const { addQuote } = useQuotes();

function handleSave() {
  if (!isValid || premium === null) return;
  addQuote({ id: Date.now(), type, age, coverageAmount, monthlyPremium: premium });
}

  2. Wire the form’s onSubmit to handleSave (keeping e.preventDefault()), and add a submit button just before the closing </form>:

    <form
  className="quote-form"
  onSubmit={(e) => {
    e.preventDefault();
    handleSave();
  }}
>
  {/* ...labels, select, and inputs stay the same... */}

  <button type="submit" className="primary-btn" disabled={!isValid}>
    Save this quote
  </button>
</form>

  3. Save and try it: fill in the form, click Save this quote, and watch your new quote appear at the top of the "Recent quotes" list on the right — across two sibling components, connected only by context.

Why this matters: QuoteForm and RecentQuotes are siblings; neither is a parent of the other. Without context you would have to lift this state all the way up to App and drill it back down to both — the equivalent of two coworkers routing every note through their shared manager. Context lets them read and write the same shared system instead, so two unrelated parts of the tree stay in sync directly.

1.12. Review

In this lab you:

  • Extracted reusable logic into a custom hook (useQuoteEstimate).

  • Built a Context provider backed by useReducer to hold shared state.

  • Eliminated prop drilling by reading the saved-quotes list from context.

  • Connected two sibling components through a dispatched action.

You refactored a working app the way your engineers keep larger React codebases maintainable — and you now know, firsthand, what "pull it into a hook" and "put it in context" actually buy a team.
