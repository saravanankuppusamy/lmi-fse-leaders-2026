Evergreen Insurance Quote Page — Rebuilding the Form in React

Lab 1

In this lab, you will rebuild the Evergreen quote page as a React + TypeScript application. The page you made interactive with plain JavaScript in Week 1, and typed in Week 2, now becomes a set of components — the reusable building blocks every modern Liberty Mutual front-end is made of.

You are not expected to become a React developer in one hour. You are here to see the three ideas at the heart of React — components, props, and state — by assembling them into a page you already know well.

1.1. A Note About Keyboard Shortcuts

Your lab VM runs inside your browser, which can sometimes capture a keyboard shortcut before it reaches the VM. If a shortcut doesn’t work — for example, Ctrl+` to open the integrated terminal — use the menu alternative instead (Terminal → New Terminal). Every shortcut in this lab has a menu path.

1.2. Why You’re Doing This Lab

When your engineers say "that’s a component," "pass it down as a prop," or "put it in state," they are describing the exact moves you are about to make. React is the framework behind a large share of the applications your teams ship. After this lab, a React pull request will read like a diagram you have drawn, not a foreign language.

1.3. What’s Already Set Up on Your Lab VM

  • Visual Studio Code, Node.js, and NPM.

  • The starter project: a React + TypeScript app (created with Vite). The page layout, styles, and premium math are provided. Three components in src/components/ have TODO comments for you.

1.4. Open the Project and Run It

  1. Launch VS Code from the lab VM’s applications menu (or the desktop shortcut).

  2. In VS Code, choose File → Open Folder, navigate to Labfiles/evergreen-quote-react-intro in your home folder, and click Open.

  3. Open the VS Code integrated terminal via Terminal → New Terminal (or press Ctrl+` ). Confirm you are in the lab folder:

    pwd

    You should see a path ending in Labfiles/evergreen-quote-react-intro.

  4. In that same terminal, install the dependencies and start the dev server:

    npm install
npm run dev

  5. Ctrl+Click the URL Vite prints (usually http://localhost:5173). The Evergreen page appears, but the form does nothing yet. You will fix that.

 Note

React’s dev server has Hot Module Replacement — when you save a file, the page updates instantly without a full reload. Watch for it as you work.

1.5. Read the Component Tree

  1. Open src/App.tsx. This is the root component. Notice it returns JSX — HTML-like syntax — and that it composes two of your components: <QuoteForm /> and <RecentQuotes quotes={sampleQuotes} />.

  2. Notice quotes={sampleQuotes} — that is a prop: data passed from a parent (App) down to a child (RecentQuotes).

Why this matters: A React app is a tree of components, each one a function that returns a piece of UI. Data flows down through props. You just read the shape of the whole app in one short file — exactly how an engineer orients themselves in a new codebase.

1.6. Render a List (RecentQuotes.tsx)

  1. Open src/components/RecentQuotes.tsx. The props are already typed for you (quotes: Quote[]). Find TODO 5 and replace it with:

    {quotes.map((quote) => (
  <li key={quote.id}>
    <span className="quote-type">{quote.type}</span> &mdash;{" "}
    <span className="quote-premium">
      {formatCurrency(quote.monthlyPremium)}/mo
    </span>
  </li>
))}

  2. Save. The "Recent quotes" panel fills with four quotes.

    Figure 1. The Recent quotes panel, rendered from the sample data with .map()

What you just used:

  • .map() turns an array of data into an array of JSX elements — the standard way to render a list in React.

  • key={quote.id} gives each item a stable identity so React can update the list efficiently. Leaving it out triggers the warning your engineers see in code review.

  • { …​ } curly braces drop JavaScript values into JSX.

1.7. Type the Props (PremiumDisplay.tsx)

  1. Open src/components/PremiumDisplay.tsx. Replace TODO 1 with the props interface, and replace TODO 2 and TODO 3 by typing and destructuring the props parameter on the function line:

    interface PremiumDisplayProps {
  premium: number | null;
  error: string;
}

function PremiumDisplay({ premium, error }: PremiumDisplayProps) {

    Destructuring { premium, error } in the parameter list handles both TODO 2 (typing the parameter) and TODO 3 (reading premium and error from props) in a single line, so the TODO 3 comment can be removed.

  2. Replace TODO 4 and the <span className="estimate-amount">—</span> placeholder on the line just below it with a single span that shows the premium (or a dash when there is none):

    <span className="estimate-amount">
  {premium === null ? "—" : formatCurrency(premium)}
</span>

    You should end up with one estimate-amount span. If the estimate later shows both a dollar amount and a leftover —, the old placeholder is still there — delete it.

  3. Save.

 Note

Saving this file won’t change the page yet. A component only appears when a parent renders it, and nothing renders PremiumDisplay until you wire it into QuoteForm in the next section (TODO 11). The estimate box appears then.

Why this matters: PremiumDisplay has no state of its own. It just receives data through props and renders it. Most components in a real app are exactly like this — small, typed, and predictable. The interface is the contract for what this component must be given.

1.8. Add State (QuoteForm.tsx)

This is the heart of the lab. Open src/components/QuoteForm.tsx.

  1. Replace TODO 6 with three pieces of state:

    const [type, setType] = useState<CoverageType>("auto");
const [age, setAge] = useState(35);
const [coverageAmount, setCoverageAmount] = useState(50000);

  2. Replace TODO 7 with the derived values:

    const isValid = age >= 18 && age <= 100 && coverageAmount >= 10000;
const premium = isValid ? calculatePremium(type, age, coverageAmount) : null;
const error = isValid
  ? ""
  : "Enter age 18–100 and coverage of at least $10,000.";

  3. Make each input controlled — its value comes from state, and typing updates state. Each TODO comment sits just above the element it describes; replace that element (and its comment) in place — don’t paste a second one below the original. Update the three inputs (TODO 8, 9, 10):

    <select
  id="coverage-type"
  value={type}
  onChange={(e) => setType(e.target.value as CoverageType)}
>
    <input
  id="age"
  type="number"
  min={18}
  max={100}
  value={age}
  onChange={(e) => setAge(Number(e.target.value))}
/>
    <input
  id="coverage-amount"
  type="number"
  min={10000}
  step={5000}
  value={coverageAmount}
  onChange={(e) => setCoverageAmount(Number(e.target.value))}
/>

     Caution

    Replace each original element — don’t add a new one beside it. If a field appears twice (a filled box with an empty box right below it), the old uncontrolled <input> is still there. Delete the leftover so each input shows once.

  4. Finally, render the display and the conditional error (TODO 11, 12):

    <PremiumDisplay premium={premium} error={error} />

{error && <p className="message">{error}</p>}

  5. Save and switch to the browser. Change the dropdown and the numbers — the estimate updates instantly. Enter an age of 5 and the error message appears; fix it and the message disappears.

    Figure 2. The finished form: controlled inputs drive a live premium estimate

Why this matters: This is the React model in one screen. State holds what can change. When you call a setter (setAge), React re-renders the component and the UI reflects the new state automatically — you never touch the DOM yourself. Compare that to Week 1, where you wrote every DOM update by hand. That difference is why teams reach for React.

1.9. Watch a Re-render

  1. Add a temporary line inside QuoteForm, right after the three useState declarations from TODO 6. It has to come after them — the log reads type, age, and coverageAmount, which don’t exist until those lines run, so placing it above them won’t compile. Position it like this:

    const [type, setType] = useState<CoverageType>("auto");
const [age, setAge] = useState(35);
const [coverageAmount, setCoverageAmount] = useState(50000);

// add only this line:
console.log("QuoteForm rendered", { type, age, coverageAmount });

  2. Back in the browser, open the DevTools Console and type in the form. Every keystroke logs a new render with the new state. Remove the line when you are done.

    Figure 3. Each keystroke re-renders QuoteForm, logged in the DevTools Console

Why this matters: Seeing "rendered" fire on each change makes React concrete: state changes → re-render → updated UI. This is the mental model behind every React conversation.

1.10. Review

In this lab you:

  • Read a React app as a tree of components composed in App.tsx.

  • Rendered a list with .map() and proper `key`s.

  • Defined and used typed props to pass data from parent to child.

  • Held changing data in state with useState and made controlled inputs.

  • Used conditional rendering to show an error only when it exists.

You rebuilt the Evergreen page the way your engineers build real applications — out of small, typed, reusable components — and saw why "let React handle the DOM" is such a powerful idea.
